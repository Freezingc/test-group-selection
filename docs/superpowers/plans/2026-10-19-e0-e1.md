# E0–E1 Implementation Plan

**Goal:** Execute the research report's first implementation handoff, preserving the distinction between pipeline checks and evidence for H1/H2. The user's request authorizes implementation, local experiments and a new GitHub repository. The supplied report is the design specification; routine implementation choices are recorded here before observing results.

**Architecture:** Generation consumes only public task views. Selection consumes candidate source and generated-test pass matrices. Evaluation reads the full pinned EvalPlus data separately. Analysis joins immutable selections and labels after selection files have been hashed. No paid API, code repair, trained gate, or E2 auditor is included.

**Tech stack:** Python 3.11, NumPy, SciPy, EvalPlus 0.3.1, local vLLM 0.11.0, Linux bubblewrap.

**Spec:** `docs/research/research-report.md`, sections 5–9 and 12.

## Global constraints

- 160 tasks selected by SHA-256 of `tgselect-v1:<task_id>`; first 20 are E0-only and remaining 140 are E1 exploration.
- Candidate pool 16; 8 separate test requests, each requesting 8 tests; temperature 0.7, top-p 0.95; at most 2048 output tokens each.
- Full model identity, weight revision, tokenizer, seed, prompt and usage logged. Resolve and save model revision before generation.
- Fixed task/candidate hash tie order; byte-identical source classes collapse only in review sets. Original candidate multiplicities remain in base ranking.
- All 20 random grouping seeds retained. Actual post-parse group sizes matched.
- No hidden reference, hidden tests or evaluation labels in generation/selection; no filtering generated tests by ground truth.
- Untrusted code runs without network, home-directory access or write access to project files; CPU, memory, process and wall-time limits enforced.
- No usable candidate remains in the denominator as failure. Infrastructure failures stop matrix analysis rather than become candidate errors.
- No E2 benefit claim from oracle candidate coverage; synthetic checks labelled synthetic.

## Tasks and verification

- [ ] 1. Pin data/model/environment and prepare public/private dataset views. Tests: task split determinism, no reference or hidden input leakage. Command: `.venv/bin/pytest tests/test_data.py -q`.
- [ ] 2. Implement selectors and invariants with tests first: fixed ties, identical-row blind spot, source deduplication, ACES-C formula, source-size matched random groups, empty candidate/test pools. Command: `.venv/bin/pytest tests/test_selection.py -q`.
- [ ] 3. Implement grouped generation and isolated execution. Tests: generated-test AST parser rejects code execution, per-test state is reset, infinite loops time out, network/filesystem cannot access host resources. Command: `.venv/bin/pytest tests/test_execution.py -q`.
- [ ] 4. Generate E0's 20 natural tasks; save every request including truncation/parse failures, then build matrices and immutable selections before hidden evaluation.
- [ ] 5. Run official EvalPlus hidden evaluation in isolation. Analyse paired coverage, added/lost coverage, rescue ceiling and identical-row blind spots. Synthetic fixtures cannot enter this table. Bootstrap by task; do not count matrix cells as independent samples.
- [ ] 6. Replay selections from frozen inputs and compare SHA-256 hashes. Run code review and required tests, write ARS Material Passport results and exact next commands. Extend to E1 only if the pipeline is reliable.
- [ ] 7. Commit source, protocol and compact experiment evidence. Create private GitHub repository and push; retain large raw logs locally with hash manifests.

## Method decisions before results

- Use the report's recommended Qwen2.5-Coder-7B-Instruct if downloadable. Any unavailable dependency/model is recorded before choosing an alternative; no model is chosen using coverage outcomes.
- Candidate/test interface is Python function-level, with generated tests restricted to a single equality assertion calling the named entry point with literal arguments. Invalid assertion formats are recorded, not silently fixed.
- Generated-test equality uses Python equality; hidden correctness uses official EvalPlus, including its task-specific tolerance and comparison handling.
- ACES-C removes constant columns and uses positive LOO AUC excess times pass-rate variance; score ties use this project's common hash order. AUC ties retain half-credit. Zero weights fall back to uniform over retained discriminating tests; if no columns remain, all scores are zero.
- Treat natural pilot output as engineering/exploratory evidence only. E0 is not part of the 140-task E1 inference denominator.
